# AdcSR タイル境界診断

診断日: 2026-09-11（JST）

測定機: GeForce RTX 5060 Ti（VRAM 約16 GB）、システム RAM 約31 GB

## 結論

現行の AdcSR 128×128、入力 overlap 16 を維持する。薄い格子状の暗部は再現したが、試した補正はいずれも画質の副作用が大きく、192/256 タイルも代替にならなかった。製品コードの変更は採用しない。

`tmp/adcsr-tile-diagnosis` の画像、ONNX、ログ、JSON は診断用であり、無視対象のためコミットには含めない。

## 再現結果

サンプルには 257×241 の写真 `tmp/photo-test-input.png` と、緩い色勾配だけを持つ合成 smooth control を使用した。現行設定は入力タイル 128、overlap 16、x4 出力で、コア幅は入力 96（出力 384）。境界のクロスフェード帯は出力側で ±64 px（全幅 128 px）となる。

写真では blend の seam/interior gradient 比が 0.8724（2.4289/2.7841）、no-blend は 1.1536（4.0616/3.5207）だった。smooth control では blend の境界部が中央部より 0.4801/255（0.1883%）暗く、no-blend は 0.1942/255 暗かった。一方、seam gradient 比は blend 0.748、no-blend 1.875 で、blend は硬い継ぎ目を大幅に抑えるものの、幅の広い低周波の明暗差を完全には消していない。ユーザーが見つけた「チョークで薄く引いたような黒い格子」と整合する。

## 比較した対策

- overlap 4/8/12/16 の seam dip は、写真で +2.399/+1.414/+0.070/-0.752、smooth で -3.188/-2.125/-1.238/-0.480。小さい overlap は smooth 側の暗部を悪化させ、増減だけでは安定した改善にならなかった。
- タイルごとの mean/std 補正を外すと、写真の低周波 seam-minus-center は -0.0286 から -0.0950 に悪化した。smooth では -0.480 の暗部が +1.111 の明部へ反転し、タイル間トーンが不安定になった。
- 全画面の低周波 residual 補正は、写真の seam dip を -0.051～-0.108 まで減らしたが、出力全域の正当な陰影も変え、変更量 MAE は 4.81～5.57。採用しない。
- global/local tone match は、写真の MAE が 2.15～3.34、smooth が 1.55～1.97。局所半径32では最大差が写真249、smooth194に達し、トーン保持と両立しなかった。
- 境界帯だけの residual 補正は、写真で MAE 0.438、最大差8、境界外MAE 0に抑えられたが、seam dip は -1.218で改善しなかった。
- blend weight を p=1/2/4 と強調しても、写真の seam dip は -0.752/-0.775/-0.781で改善せず、smooth の改善も -0.480/-0.341/-0.251に留まった。
- 隣接タイル間のトーン合わせは、8-bit換算で最大1階調に制限すると写真の seam dip が -0.775、smooth が -0.480で、実質的な改善がなかった。

## 192/256 タイル実験

192版ONNXは入力 `(1,3,192,192)`、出力 `(1,3,768,768)` でexportでき、Torch/ONNX Runtimeの出力はPSNR無限大（数値上の完全一致）だった。写真とsmoothをoverlap 16/24で各4タイル実行し、すべて完走した。

| サンプル | overlap | seam dip | seam gradient | 128 blend16との差MAE | 最大差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 写真 | 16 | -1.789 | 3.491 | 3.537 | 114 |
| 写真 | 24 | -0.289 | 3.358 | 3.390 | 119 |
| smooth | 16 | +0.419 | 0.410 | 63.644 | 200 |
| smooth | 24 | +0.307 | 0.424 | 63.699 | 209 |

写真のoverlap 24だけを見ると暗部は減るが、smoothで128版との差が極端に大きく、モデルの挙動を保った置換にはならないため192版は採用しない。

256版ONNXもexportでき、写真・overlap 16だけは4タイルで完走した（推論合計29.70秒、wall 33.85秒、128版との差MAE 23.86、最大差255）。写真・overlap 32は約133秒後にDirectMLエラー `887A0006` で失敗し、smoothの試行も出力を完了できなかった。RAM/VRAMを使い切る挙動も確認されたため、256版は実用候補から外す。

## 判定

現時点では、128 overlap 16のblendが最も安全である。blendを切ると硬い境界が増え、stats除去・事後補正・トーン合わせ・タイル大型化には、格子をわずかに減らす以上の副作用または互換性リスクがある。診断結果は将来モデルや合成方式を再検証する際の基準値として残す。

## 追記（2026-09-11）: overlap 32 を AdcSR の既定に採用

本機（Radeon 860M）で overlap 32/48 と周期プロファイル除去を検証した（tmp/adcsr-seam/RESULT.md）。
平坦なグラデーション画像では seam dip が overlap 16 の −1.30 階調から 32 で −0.56 階調に半減し、48 では上積みがなかった。
実写 tos（1280x534）の差分折り畳み評価でも、ov16 の P=384 格子成分 0.45〜0.80 階調が ov32 で P=256 の 0.24〜0.40 階調まで減り、ov32→ov48 の改善は小さく頭打ちだった。
周期プロファイル除去は、ピッチを P と互いに素な 383 にした対照実験でも本番と同量（MAE 約1.2）の変化が出て内容物を壊すため不採用とした。
以上から AdcSR の serve overlap 既定を 32（128 タイル・コア 64）に変更した（他モデルは 16 のまま）。
代償は処理時間が約 2.2〜2.4 倍で、tos は 180 タイルで約 4.5 分になる。
